02

База: що вмикає кожен

Ці речі вбудовані в Claude Code або є стандартом де-факто. Без них решта інструментів працює гірше.

Пам'ятьБаза

CLAUDE.md

Інструкції проєкту, які Claude читає на старті кожної сесії: стек, команди збірки, конвенції, заборони. Створюється командою /init.

./CLAUDE.md · ~/.claude/CLAUDE.md
РежимБаза

Plan Mode

Claude спершу досліджує код і пропонує план, нічого не змінюючи. Якщо добре відшліфувати план, реалізація часто виходить з першої спроби.

Shift+Tab · перемикання режимів
КонтекстБаза

/context · /clear · /compact

Показують, що займає вікно контексту, очищують його та стискають історію. Тримати контекст «чистим» — головна навичка.

/context → аудит токенів
БезпекаБаза

Permissions у settings.json

Allow- і deny-списки для команд та інструментів. Безпечні команди проходять без зайвих підтверджень, а небезпечні заблоковано.

.claude/settings.json · /permissions
MCPТоп

Context7

Свіжа документація під версію вашої бібліотеки, тож модель не вигадує неіснуючих API.

/plugin install context7
MCPТоп

GitHub

Робота з репозиторіями, PR, issues, CI. Альтернатива без MCP: CLI gh, який Claude чудово використовує сам.

/plugin install github
НавігаціяБаза

@файли та !команди

@src/App.tsx додає файл у контекст, а ! npm test запускає команду й передає вивід у розмову.

@ · ! · Esc Esc (rewind)
СесіїБаза

/resume і claude -c

Повернення до попередніх розмов. Знадобиться, щоб продовжити довгу задачу завтра з тим самим контекстом.

claude --continue · /resume
03

Плагіни і скіли

Скіл — це папка з SKILL.md та інструкціями, які підвантажуються лише тоді, коли потрібні. Плагін — це пакет, у якому можуть бути скіли, агенти, хуки, команди та MCP. Встановлюється через /plugin.

04

MCP-сервери

MCP (Model Context Protocol) підключає зовнішні інструменти. Порада зі спільноти: якщо ставити лише п'ять, то це Context7, GitHub, Playwright, файлова система і один сервер під ваш стек. Кожен сервер займає контекст, тож не вмикайте зайвих.

БраузерТоп

Playwright MCP

Найвживаніший сервер у спільноті. Claude сам відкриває сторінку, клікає й перевіряє свій UI.

microsoft/playwright-mcp
БраузерТоп

Chrome DevTools MCP

Debugging у справжньому Chrome: консоль, мережа, performance-трейси й Lighthouse.

ChromeDevTools/chrome-devtools-mcp
КодСкарб

Serena

Семантична навігація на основі LSP: пошук символів, посилань і рефакторинг. Claude Code не індексує кодову базу, і Serena закриває цю прогалину.

oraios/serena · MIT
ДаніБаза

PostgreSQL / Supabase

Інтроспекція схеми й запити до живої БД. Для безпеки вмикайте режим read-only.

~5 хв налаштування
ВебСкарб

Firecrawl

Скрейпінг і пошук у вебі з чистим markdown на виході. Корисний для ресерчу документації.

firecrawl/firecrawl-mcp-server
МисленняСкарб

Sequential Thinking

Покрокове структуроване міркування. Найкраще працює в парі з Serena на складних рефакторингах.

modelcontextprotocol/servers
ДеплойБаза

Vercel · Sentry · Linear

Деплої, помилки з продакшену й задачі команди, доступні прямо з терміналу.

офіційні remote MCP
05

Агенти (subagents)

Субагент працює з окремим контекстом, власним system prompt і набором інструментів. Він ізолює важку роботу від головної сесії. Типова помилка — роздрібнювати все на агентів: задачу, яка вимагає глибокого розуміння коду, краще лишити в головній сесії.

ВбудованийБаза

Explore · Plan

Explore робить швидкий пошук по кодовій базі тільки на читання. Plan проєктує план реалізації.

вбудовані в Claude Code
СвійБаза

code-reviewer

Найпопулярніший власний агент. Має лише права на читання й перевіряє код після кожної фічі.

.claude/agents/code-reviewer.md
СвійБаза

test-runner · debugger

Запускає тести й повертає лише суть помилок, а не тисячі рядків логів.

/agents → Create new
КолекціяТоп

wshobson/agents

Велика колекція готових спеціалістів: backend, frontend, DevOps, security тощо.

github.com/wshobson/agents
ПатернСкарб

Архітектор → Dev → Критик

Тріо агентів, де критик тільки читає код і виносить вердикт. Такий самоконтроль ловить хиби до того, як вони закріпляться в коді.

як у вашому .claude/agents
ПаралельністьСкарб

Git worktrees

Кілька сесій Claude паралельно, кожна у своїй копії репозиторію, без конфліктів.

claude --worktree · git worktree add
06

Хуки і правила

Хуки — одна з найбільш недооцінених можливостей. Їх виконує сам harness, а не модель, тому вони спрацьовують гарантовано. Правила в CLAUDE.md модель лише «бере до уваги».

PostToolUseБаза

Автоформатування

Після кожного Edit/Write запускаються Prettier і ESLint --fix, тож код завжди в стилі проєкту.

matcher: "Edit|Write"
PreToolUseБаза

Захисні блокування

Блокують rm -rf, push у main і редагування .env. Хук повертає exit code 2, і дія скасовується.

exit 2 = block
Stop / NotificationСкарб

Сповіщення

Звук або toast, коли Claude закінчив чи чекає на вас. Можна піти по каву.

"Stop": [...]
SessionStartСкарб

Динамічний контекст

На старті сесії підкладає git status, відкриті задачі або дату. Так працює автоактивація Superpowers.

additionalContext
ПравилаБаза

Ієрархія CLAUDE.md

Глобальний ~/.claude/CLAUDE.md → проєктний → вкладені в підпапках. Тримайте файли короткими: кожен рядок займає контекст.

/memory · /init
ПравилаСкарб

Slash-команди як промпти

Власні команди в .claude/commands/*.md — це шаблони user-промптів, які модель сприймає з вищим пріоритетом, ніж system prompt.

$ARGUMENTS · frontmatter
07

Приховані скарби

Про ці інструменти пишуть рідко, але ті, хто їх спробував, зазвичай уже не відмовляються.

CLIСкарб

ccusage

Аналізує локальні логи: скільки токенів і грошей пішло по днях, сесіях і 5-годинних блоках.

npx ccusage@latest
StatuslineСкарб

ccstatusline

Красивий statusline з модельлю, гілкою, заповненістю контексту й вартістю в реальному часі. Підтримує powerline і теми.

npx ccstatusline@latest
ОркестраціяСкарб

claude-squad

TUI для керування кількома агентами (Claude Code, Codex, Aider), кожен у своєму worktree.

smtg-ai/claude-squad
Пам'ятьСкарб

claude-mem

Автоматично записує, що робив Claude, стискає це й підкладає релевантний контекст у наступні сесії.

thedotmack/claude-mem
ХукСкарб

tdd-guard

Хук, який не дає писати реалізацію, доки немає тесту, що падає. Справжній TDD без поступок.

nizos/tdd-guard
ТокениСкарб

Caveman · CodeBurn

Caveman стискає вихідні токени в середньому на ~65%. CodeBurn локально рахує витрати в 40+ інструментах.

npx codeburn
КонтекстСкарб

Repomix

Пакує весь репозиторій або його частину в один файл, зручний для AI. Знадобиться для аналізу чужого коду.

npx repomix
ВбудованеСкарб

Esc Esc / rewind

Відкат розмови і змін у файлах до будь-якої попередньої точки. Це безпечна «машина часу» для експериментів.

/rewind
HeadlessСкарб

claude -p у скриптах і CI

Неінтерактивний режим для пайплайнів: генерувати changelog, перекладати, рев'юїти PR у GitHub Actions.

claude -p "..." --output-format json
08

Роудмапи вивчення

Чотири траєкторії: від першого запуску до автономних агентів у CI. Проходьте послідовно, бо кожен етап спирається на попередній.

🌱 Старт

1–2 тижні · перші результати

  1. Крок 1Встановлення і /initЗгенеруйте CLAUDE.md і відредагуйте його вручну: стек, команди, заборони.
  2. Крок 2Режими і Plan ModeShift+Tab. Звикніть спершу планувати, а потім кодити.
  3. Крок 3@файли, !команди, Esc EscТочково передавайте контекст, а якщо щось пішло не так, відкочуйтеся.
  4. Крок 4Гігієна контексту/context, /clear між задачами, /compact у довгих сесіях.
  5. Крок 5PermissionsДозвольте безпечні команди в settings.json, щоб підтвердження не перебивали роботу.

🔧 Кастомізація

2–4 тижні · свій тулкіт

  1. Крок 1Перші плагіни/plugin: frontend-design, context7, code-review.
  2. Крок 2Перші MCPPlaywright і GitHub. Подивіться через /mcp, скільки контексту вони займають.
  3. Крок 3Власні slash-командиВинесіть промпти, які ви повторюєте, у .claude/commands/.
  4. Крок 4Перший хукPrettier на PostToolUse і сповіщення на Stop.
  5. Крок 5Statusline і ccusageСлідкуйте за контекстом і витратами.

🤖 Агенти та скіли

1–2 місяці · делегування

  1. Крок 1Superpowers-процесbrainstorm → plan → TDD → verify як щоденний ритм.
  2. Крок 2Перший субагентcode-reviewer тільки з правами на читання через /agents.
  3. Крок 3Власний скілЗа допомогою skill-creator з евалами перетворіть повторювані виправлення на скіл.
  4. Крок 4Мультиагентні патерниАрхітектор, розробник і критик. Ізоляція контексту.
  5. Крок 5WorktreesПаралельні сесії над різними фічами.

🚀 Автоматизація

постійно · рівень команди

  1. Крок 1Headless claude -pСкрипти з JSON-виводом.
  2. Крок 2GitHub ActionsАвтоматичне рев'ю PR і виправлення через @claude у коментарях.
  3. Крок 3Свій плагін або маркетплейсПоширте скіли, агентів і хуки на всю команду.
  4. Крок 4Власний MCP-серверПідключіть внутрішні API компанії (TypeScript SDK).
  5. Крок 5Agent SDKВласні агенти на тому самому рушії, що й Claude Code.

React 19 + TypeScript + Vite. Стилі: CSS Modules.

## Commands
- `npm run dev`   — dev-сервер
- `npm test`      — Vitest
- `npm run lint`  — ESLint, обов'язково перед комітом

## Conventions
- Лише .ts/.tsx і .css, без .js
- Компоненти: named export, props через interface
- Стан: локальний useState → Context; без Redux

## Don't
- Не чіпати src/generated/
- Не додавати залежності без питання
